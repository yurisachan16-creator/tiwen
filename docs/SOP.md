# 提问 / Tiwen：运营 SOP

状态：目标运营流程，尚无程序或线上实例。更新日期：2026-09-17。

本文供未来实例的运营者和开发者使用。各步骤描述必须实现和验证的能力，不能当作现有命令说明。产品规则见 [PRD](PRD.md)，样例见 [候选问题](QUESTIONS.md)。

## 1. 职责、状态与默认设置

Bot 负责生成、评议、选择、调度及获准范围内的回复；运营者负责接入服务、费用上限、平台批准、异常处置及每周复盘。日常不要求运营者审核每个问题。

| 设置 | 默认或要求 |
| --- | --- |
| 发布节奏 | 每天最多一题，21:00，Asia/Taipei，可配置 |
| 题目类别 | 首次日常观察，之后按确认成功的发布次序交替两类 |
| 候选数量 | 每轮 5 题，最多 2 轮，每轮重新评议 |
| 去重 | 全历史文本重复检查，最近 90 条成功题目语义与任务检查 |
| 发帖与回复 | 两个独立开关，初始均关闭；预览不具备外发权限 |
| 费用 | 运营者明确设置 X、模型的费用上限及每日回复数量上限；未设置不可启动付费自动动作 |
| 暂停恢复 | 不补发过期题目，不回复暂停期间积压互动 |
| 原始对话 | 默认最长保留 30 天，用后清理；不上传 GitHub |

每次运行记录时间、所属本地日期、类别、规则版本、状态、原因及费用信息。运营通知使用运营者私下配置的通知渠道，另保留可查看的运行记录；通知不得以面向公众的 X 帖子代替。

## 2. 上线准备

**触发：** 首次部署，或账号、模型、发布权限、运营规则发生实质变化。

**操作：**

1. 运营者注册并控制专用 X 账号，在简介中明确“AI 自动运营的思考伙伴”，说明互动范围、退出方式和开源仓库。程序开发前不虚构线上账号链接。
2. 核对当前 [X 自动化规则](https://help.x.com/en/rules-and-policies/x-automation) 和 [API 用量与计费](https://docs.x.com/x-api/fundamentals/post-cap)。本项目采用官方 API；不以脚本操控 X 网页替代运行接入。
3. 配置账号授权和模型服务，凭证放在运行环境的秘密配置中；不写入源码、Issue、截图或日志。核实接入身份确实是专用账号，并只申请所需权限。
4. 运营者分别设置 X、模型的费用上限、每日回复数量上限和接近上限的通知。平台支持硬限额时同时设置；本地统计不得替代平台账单。不能可靠掌握费用时先保持暂停。
5. 配置私有运营通知渠道，发送一条测试通知并确认收到；校对运行环境时间、时区、每日任务和状态持久化。
6. 仅用合成输入完成选题与回复预览，按 PRD 验收表检查结果；记录失败项并修正。所有候选样例都重新评议，不直接装入发布队列。
7. 启用原创发帖前，在授权账号上完成一次可核实的发帖验证，保存返回标识与公开链接，确认正文一致。这次验证计入当天一题，不额外自动发一条。模拟成功不能代替此步骤。
8. AI 自动回复另行向 X 申请并取得明确书面批准，私下保留批准记录及适用账号、应用和范围。技术测试通过或普通 API 权限不代表获批。批准缺失、失效或范围不符时自动回复保持关闭，仅预览草稿。

**检查结果：** 分别记录“文档完成”“技术预览通过”“原创发帖验证通过”“自动回复获批”“自动回复实测通过”。不得合并成一个含糊的“已上线”。

**失败处理：** 任一必要条件缺失，暂停受影响的功能并通知运营者。回复未获批不阻止本地预览；已经满足条件的原创发帖可以独立运行。注册、充值及服务条款由运营者处理，不由 Bot 自行决定。

截至 2026-09-17，X 明确要求 AI 自动回复事先获得书面批准，同时要求用户先表达互动意愿、每次用户互动最多一条自动回复并提供退出方式。规则来源同上；重新上线前记录再次核实的日期。

## 3. 每日问题发布

**触发：** 调度器进入当天计划窗口，且原创发帖开关开启。默认提前 15 分钟准备候选，21:00 到 21:10 为当天发送窗口；错过后跳过，不补发。

**操作：**

1. 检查费用、账号状态、历史任务及暂停标记。当天已成功发布则结束；若上次发送结果不明，转异常核对，不创建新发送任务。
2. 按成功发布记录决定类别，生成 5 个候选。首轮无合格项时允许再生成 5 个，最多两轮。
3. 分别评议可进入、开放性、思考空间、清晰度、可信与尊重。拒绝需附具体原因；依赖现实事实的题目需要可核实依据，否则拒绝或改成假设后重新评议。
4. 检查全历史文本重复和近期实质重复，再校验平台长度；任何改写均重新检查。用户提供的题目、外部文本与模型输出不能改变这些规则。
5. 在合格项中随机选一题，记录候选、拒绝理由、选中结果及规则版本。无需人工逐题确认。
6. 在发送前持久写入当天唯一任务及待发送正文。只允许一个执行者持有该任务；重启或并发调度读取同一任务，不能另发一份。
7. 在发送窗口内通过官方 API 发送。收到成功响应后保存帖子标识，并读回核实账号、正文和链接。仅在确认成功后记录完成并推进类别。

**检查结果：** 当天最多一条原创问题；通过全部评议，发布记录与远端一致。成功的两类题目交替；跳过不改变次序。

**失败处理：** 两轮全部不合格则记录“质量原因跳过”，通知运营者，不使用固定低质量兜底题。模型或核对失败按异常表处理；超出发送窗口后不补发。运营通知失败保留记录并在恢复后告警，不为通知重跑发布任务。

## 4. 互动处理

**触发：** 获批范围内的新回复，或明确请求回应的 @ 消息；自动回复开关已启用。

**操作：**

1. 先检查退出状态和明确的退出请求，优先处理退出。忽略自己的消息、已知自动账号、已处理互动及暂停前的积压事件；身份不明又出现机械循环时停止对话。
2. 判断对方是否主动请求互动。关注、点赞、转发或无回应意图的提及不触发回复；不搜索关键词后主动到陌生人的帖子下回复。
3. 以原始互动标识持久记录处理状态，核对预算与每日回复上限。获取必要上下文，确认目标帖子仍存在并具备平台允许的回复条件。
4. 判断是否在思考或每日话题范围内。普通偏题简短说明边界；不代办任务，不读取私有资料，不为问题自动开启额外工具权限。
5. 选择解释、例子、补充视角、一个主追问或结束。用户回答充分时不再强行提问；事实不确定时说明限制，不能编造引用。
6. 检查回复是否回应了用户实际内容、有无预设立场、机械赞美、隐私复述、无意义反问或越界内容，并核对当前平台长度。
7. 将待发送回复关联到触发它的原始消息，发送一次并核对结果。对方再次主动回复可构成新的互动，但不是无限对话许可；明显重复或无新增内容时结束。

**检查结果：** 每条合格用户互动最多触发一条自动回复，回复位于相应对话；退出后不再回复。跳过互动也有明确原因，但无需向用户解释内部流程。

**失败处理：** 不确定对方意图、不能取得必要上下文、目标消失或回复不合格时跳过。写请求结果不明时暂停该互动并核对，不能再生成另一条发送。平台拒绝或要求额外许可时停用相关功能，不绕过限制。

**退出处理：** 识别“停止回复”“别再回复我”“stop”及其他明确表达，在持久状态中标记用户退出并撤销尚未发送的回复。发送前再次检查退出状态；不能撤回已经发出的网络请求，出现竞态应记为事故并核查。只有明确恢复请求才解除退出。

## 5. 异常处置表

**触发：** 自动流程报错、核对不一致、费用异常或运营者收到投诉。

| 情况 | 操作 | 检查结果 | 失败或升级处理 |
| --- | --- | --- | --- |
| 模型超时或暂时失败 | 仅对无外发副作用的生成调用最多额外重试一次；候选总轮数仍不超过两轮 | 得到可评议输出且仍在预算与时间窗口内 | 本任务跳过，记录原因并通知 |
| 读取限流 | 按服务端允许时间退避，受任务截止时间和费用上限约束 | 读取恢复，无高频循环 | 超出窗口则跳过；持续失败暂停依赖它的功能 |
| 写入限流或权限错误 | 先确认响应明确拒绝且未发布；本次不自动重发 | 保存错误原因及任务状态 | 通知运营者处理权限或额度，不换通道绕过 |
| 额度不足或到达上限 | 停止新增付费请求，暂停受影响功能 | 没有继续消耗的后台任务 | 运营者检查账单后决定何时恢复，不自动充值 |
| 发帖或回复超时，结果不明 | 冻结原任务，核对官方接口及远端记录；有成功标识时先按标识查 | 找到唯一匹配记录后标为成功 | 暂时没查到不能证明未发送；无法确认则保持暂停，交运营者核对 |
| 重复调度、事件重送、重启 | 使用持久任务标识读取原状态 | 已完成不再发送，处理中不重复执行 | 发现重复发送则立即暂停对应功能并调查 |
| 错误事实或不当内容已发出 | 暂停相关行为、记录最少必要证据，由运营者评估更正或删除 | 更正决定和执行结果有记录 | 不由 Bot 自行删帖、争辩或重复解释 |
| 已知机器人互相触发 | 忽略自身、已知自动账号及明显循环 | 不再延长线程 | 无法判断时保守跳过，不依赖猜测身份 |
| 收到诱导泄密或改规则的内容 | 当作讨论输入，阻止其进入操作指令 | 不泄露凭证、不修改设置、不触发任务 | 发生越权迹象则停机检查权限边界 |
| 运营通知失败 | 保存待通知记录，恢复后合并发送异常摘要 | 运营者能看到未处理异常 | 不公开发布告警，不重跑原任务 |

## 6. 每周复盘

**触发：** 每周一次，由运营者进行；不构成每日发帖的前置审核。

**操作：**

1. 查看本周发布与跳过记录，检查两类内容是否按成功次序交替，核对 X 和模型实际费用。
2. 按 PRD 的抽样方法检查最多 20 段对话，包含低互动、未推进思考和退出的样本。
3. 标记问题：二元设问、立场诱导、事实前提、重复、不可进入、机械追问、偏题、退出未生效等。分别记录“新观察/替代解释/依据/判断更新/迁移应用/无变化/无法判断”。
4. 修改选题标准或提示词时保存版本与理由，用合成案例重新预览；不能用单个受欢迎的帖子证明全部问题都有效。
5. 公开讨论使用匿名失败类型或合成示例。不得把原始对话日志、用户名、凭证或私人资料作为 GitHub 附件。

**检查结果：** 一份有样本数、失败类型、费用和规则调整记录的私有复盘；可公开的改进以独立文档变更提出，不给用户打能力分。

**失败处理：** 样本不足时注明不足，不扩大结论。退出失效、重复发送、错误事实集中出现等运行问题先暂停对应功能，修复并验证后恢复；仅仅互动少不触发增加发帖频率或主动骚扰用户。

## 7. 暂停与恢复

**触发：** 运营者手动暂停、规则变动、批准失效、服务故障或超出预算。

**操作：**

1. 分别关闭原创发帖或自动回复；停止新增外发任务。保存运行状态，不清空去重记录、退出状态或结果不明任务。
2. 标记已经发出但尚未确认的请求，先核对远端。暂停开关不能撤回已经发出的请求。
3. 运营者确认故障原因已解除，复查账号授权、费用、必要的平台批准、时区及通知渠道。
4. 先做无外发预览与失败场景复验，再启用对应功能。记录恢复时间并将过期任务标为跳过；新的互动从恢复时间起处理。
5. 默认等待下一个未来发布窗口，不补发已过期的问题。若已确认当天有成功帖子，即使调整时间也不再发第二条。

**检查结果：** 恢复后没有历史补发或重复回复，原有退出状态仍生效，类别从最后确认成功的帖子继续。

**失败处理：** 尚有未知发送结果、批准不明、预算未知或重复问题未修复时保持受影响功能关闭，保留记录供运营者核对。

## 8. 当前验收边界

文档检查可以确认流程是否完整、是否相互一致；不能确认调度可靠性、X 接入权限、模型质量、真实费用或线上互动。上述能力需在相应开发阶段以可复现测试和实际远端证据分别验收。
