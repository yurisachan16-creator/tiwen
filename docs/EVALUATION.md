# 质量评测与验收

## 三种证据分别记录

| 证据 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 离线单元和 HTTP 测试 | 输入验证、有限轮数、退出优先、错误处理、本地接口边界 | 模型实际能写出好问题 |
| 离线编辑样例 | 解释产品意图、展示界面和选择过程 | 自动评议准确率或受众喜好 |
| 真实模型结果与人工盲评 | 特定模型、提示词、样本上的表现及已发现问题 | 普遍效果、提高智力或长期运营可靠性 |

## 基线材料

- `content/questions.json`：原始30题的逐题校准，保留原文、建议、理由与局限；[校准草案](CALIBRATION.md) 为阅读版本。
- `content/evaluation.json`：12个选题案例，包含7类明确缺陷、合格例子、边界例子与语义重复。`discuss` 表示需要讨论，不强行打分。
- `content/dialogues.json`：10种合成对话，覆盖简短回答、充分回答、异议、概念解释、偏题、退出、未核实事实、注入、自然结束及隐私边界。

这些是开发校准集，不能一边调提示词一边把同一集合的分数当独立泛化结果。上线前由维护者另留至少10条未参与调整的题目和5段新对话作为保留集；记录样本数、版本、模型与失败项。

## 运行方式

`npm run check` 执行真实程序测试与文档一致性检查，不调用付费模型。

`npm run evaluate` 列出编辑基线和预期行为；**不会输出虚假的模型通过率**。

配置本机模型后，逐条执行：

```sh
npm run evaluate -- --live --case=binary
npm run evaluate -- --live --case=complete
```

每次明确选择一个案例，避免一条命令意外运行整套付费请求。案例编号在两个集合中保持唯一；对话也可在网页情境中测试。模型返回 JSON 不是有效质量证明，需人工阅读正文与理由。

## 人工校准

第一轮从两类各取5题，隐藏“原题/改写题”、来源和模型名称，让维护者分别记录：是否愿意回答、能否立刻想到入口、是否像作业、是否暗含立场。开放式记录“不想答”的原因，不要求认可改写。

再比较原题与改写，只有双方一致确认的编辑原则才进入下一版提示词。没有反馈时，校准任务保持待验收，不将助手的编辑建议标成用户品味标准。

对回复分别标记是否贴题、是否带来一个有用细节、是否该结束却继续追问。可接受多种动作和措辞，别把示例答案逐字匹配当质量测试。

## M1 验收边界

程序检查与浏览器预览通过，可交付本地技术预览。M1 的编辑口径仍需维护者审定。真实模型接入按维护者决定延后：本轮仅验收可配置接口与模拟契约测试，不启用付费模型，不宣称模型质量通过。实际接入、效果与调用消耗另建后续任务，在 M2 对外发布前完成。

未取得 X 自动回复批准不阻塞本地预览，但阻塞未来自动回复上线。当前没有 X 连接能力，不能产生真实运营证据。

## 本轮新增的检查

逐题对照 `original`、`originalFocus`、当前题干与 `focus`，检查事实前提、限制条件和思考动作是否保留。`copyedit` 改掉其中任何一项都要改标为 `task-redesign`，说明变化并重新评议。字段齐全只能证明记录完整，程序不能代替人判断两个题目是否在问同一件事。

读回复时额外记录：是否先点评用户而没有新内容；是否机械复述后转折；是否在已回答充分或已道谢时继续追问；是否把普通结束当成明确退出。不要用禁词表或问号数量代替这些判断。

`content/holdout.json` 提供本轮新增的10题和5段对话，绑定提示词版本 `m1-2026-09-17.2`。输入与运行时样例分开存放，不进入提示词；它们是待维护者确认的验收材料，还不是模型通过的证据。对话仅给可接受动作与人工检查点，不要求逐字匹配一种答案。

以后配置模型后，可以逐条运行：

```sh
npm run evaluate -- --live --case=holdout-q01
npm run evaluate -- --live --case=holdout-d02
```

结果标明 `holdout`、`development` 或 `runtime-example`。运行时用过的4个样例只能做回归检查，不能计入独立效果。若依据保留集结果调整提示词，这批输入转为开发材料，重新准备未参与调整的10题和5段对话；脚本会拒绝直接把旧版本保留集用于新版本。

先保存未经润色的模型输出，再由维护者盲评。允许多个合理动作；记录样本量、版本、失误和调用数，不把结构测试分数当表达效果。`holdout-d05` 的明确退出由程序拦截，预期模型调用数为0，应单列，不能算模型能力。

本轮只检查输入隔离、样例引用、版本和回复契约，真实模型评测仍留在 #9。人参与上线前校准和定期复盘，日常自动选题不增设人工批准步骤。

## 首轮编辑反馈：入口是否清楚

本轮展示的是提交 `05f3ea4` 的10道当前题干，两类各5题，隐藏分类与编辑记录后打乱顺序。它是维护者对题库的口味校准，不是模型测试，也不是受众调查。

- 愿意回答：第7题，对应 B12（每天只能观察十分钟，怎样估计小岛上的鸟数）。
- 不愿意回答：A05、B08、A11、B01、B04、A04、B13、A10、A06。
- 对其余九题给出的共同原因：不知道从哪里着手。没有分别取得“像作业”或“暗含立场”的评分，不能替维护者补判。

这次反馈只确认了回答意愿，B12 未因此自动通过事实、质量或发布审核；其余题也不直接标为永久淘汰。

下一轮待验证的解释：题干是否给出了明确目标、可操作的对象和有用的限制，让读者能想到第一步。B12 的十分钟限制可能提供了这个入口，但单个例子不足以说明维护者只喜欢实验题、数字题或方案题。先用少量新题比较，再决定是否修改运行时提示词，不把猜测写成已确认的偏好。

下面三题仅用于下一轮编辑讨论，不进入运行时提示词、当前题库或独立模型保留集：

1. 假设你有两条上班路线：A近但红灯多，B远但很少等红灯。你有一周时间，每天只能试走一条，怎样比较哪条通常更快？
2. 假设要找出冰箱里哪一层最冷，你只有一支温度计，而且开门会影响温度。你会怎样测？
3. 假设8个人一起讨论，常常只有两个人说话。不能点名轮流发言，也不能延长时间，你会改哪一条讨论规则？

下一轮同样先收集想不想答，以及能不能想到第一步；没有反馈前不宣称问题已经更好。
