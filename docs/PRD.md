# 提问 / Tiwen：产品需求

状态：已确认的产品方向，尚未实现。更新日期：2026-09-17。

本文规定目标行为；[SOP](SOP.md) 规定运营步骤；[候选问题](QUESTIONS.md) 用于讨论和验收，不代表已发布内容。

## 1. 问题与目标

当获取答案变得容易，人仍需要主动观察、组织解释、比较依据和尝试新思路的机会。Tiwen 将这些机会放进用户已经使用的 X 时间线，通过一个具体的问题降低参与门槛。

主要用户是愿意进行短时思考的中文 X 用户，不要求专业背景，也不要求公开个人经历。开源贡献者可以改进题目、质量标准和后续实现。

目标：每天提供一个值得思考的问题，并在用户主动互动时给出贴合上下文的回应。成功不等于用户同意 Bot，也不等于对话越长越好。

## 2. 已确定的范围

| 项目 | 决策 |
| --- | --- |
| 载体 | 一个 X 账号；用户通过关注、评论、主动 @ 参与 |
| 语言 | 首版中文，文档以中文为主，README 附英文简介 |
| 选题 | AI 全自动生成、检查和选择，无日常人工选题关卡 |
| 内容比例 | 日常观察、跨领域挑战按成功发布次序交替；每类内随机选择 |
| 节奏 | 每天最多一条原创问题，默认 21:00，Asia/Taipei，可配置 |
| 回复范围 | 思考、概念解释和每日话题；不承担通用任务执行 |
| 账号性格 | 好奇、友善、表达清楚，能够提出不同看法，不训导或机械夸奖 |
| 当前交付 | 文档与仓库；不包含 Bot 代码、X 注册、部署或实际发帖 |

首版不做独立应用、用户账户体系、私信问答、付费订阅、自动点赞或主动向陌生人推销互动。运行模型、服务部署与 API 具体接口在程序开发阶段验证确定；本轮不锁定未经验证的实现或声称已支持某个服务。

## 3. 用户体验

### 3.1 每日问题

时间线上一条独立短帖即可理解，不依赖外链、前一天的内容或专业术语。关注账号不保证每条内容都会送达，产品不承诺 X 时间线或通知必达。

日常观察题允许从公共物品、场所或虚构例子回答，不默认用户有某种职业、亲密关系或情绪经历。跨领域题使用生活可理解的场景，让用户有足够信息开始推理。

### 3.2 主动互动

用户回复每日问题，或明确 @ 账号希望得到回应时，Bot 阅读必要的当前对话，再选择以下行为之一：

- 解释一个相关概念，说明其适用范围。
- 给出贴合回答的例子、反例或替代解释。
- 针对尚未展开的一点追问；一次最多一个主问题。
- 认可已经完成的推理并结束，或不回复没有新增内容的消息。

不得把每条消息都转成反问，不以“你真有洞见”等固定赞美开头，不把某种价值观当标准答案。遇到具体知识问题，可以直接回答；不确定时说明不确定，不能编造事实或来源。

### 3.3 边界与退出

偏题时给出简短边界说明，不连续劝用户回归。仅关注、点赞、转发或被动提及不视为请求自动回复。只处理用户发起的互动，不追着未回复的人发消息。

“停止回复”“别再回复我”“stop”等明确退出表达应立即生效，优先于对话生成；不发送额外确认回复。再次参与不会自动解除退出，仅明确要求恢复才解除。不得从显示名推断用户是人或机器人；对自身消息、已知自动账号及明显循环停止响应。

## 4. 自动选题与质量标准

### 4.1 选题流程

按上一条**确认发布成功**的问题决定下一类，首次为日常观察。每轮生成 5 个候选，经过质量检查后在合格候选中随机选择一个；无合格项时最多再生成一轮。两轮仍不合格，则跳过当日并通知运营者。跳过不推进类别；发布结果不明时先冻结进度并核对。

候选生成和质量评议分成独立步骤，后者必须给出具体拒绝理由，不能仅输出“高质量”。独立步骤不意味着事实已经查证，也不要求部署多个 Agent。

保存历史原创题目的正文与主题；检查全部历史中的文本重复，并与最近 90 条成功发布题目比较情境和思考任务是否实质重复。换词复述仍算重复。没有可靠事实依据的现实断言应拒绝，或改成明确的假设场景；模型自称确信不能代替查证。

### 4.2 必须通过的检查

| 维度 | 通过的表现 | 应拒绝的表现 |
| --- | --- | --- |
| 可进入 | 有具体对象、情境或可选择的例子 | 抽象到无处下手、依赖冷门背景 |
| 开放性 | 容许不同解释、方法或观察 | 假二选一、把争议前提当事实、诱导认同 |
| 思考空间 | 需要观察、解释、证据、设计或迁移 | 一句口号即可结束、纯记忆问答 |
| 清晰度 | 一次一个主任务，短帖本身可理解 | 堆砌多个任务、术语或修辞 |
| 可信与尊重 | 区分事实与假设，允许非个人化回答 | 错误事实前提、索取隐私、羞辱或诊断用户 |

五项全部通过才进入候选池。形式上开放不代表质量合格；“为什么”不能挽救一个已经限定答案的问题。该规则只约束提问质量，不要求所有问题必须引发争论。

发布前另行核对 X 当前加权字符限制；不得按普通字符数估算后强行截断。改写后的内容重新评议。具体字符计算由开发阶段选择符合当前平台规则的实现。

### 4.3 内容与提示词贡献

[30 个候选问题与改写](QUESTIONS.md) 分为两类各 15 个，均为待评议样例。贡献者应说明希望练习的思考动作、可能的回答路径与题目局限，不能仅以“有深度”作为理由。

## 5. 运行与数据要求

- 发帖、回复有独立暂停开关；初始均关闭。AI 自动回复还需平台批准这一独立条件。
- 发送前持久记录当天发布任务或用户互动标识；重启、重复事件或网络重试不得造成多次发送。
- 结果不明时进入待核对状态；只有确认成功才完成任务。无法确定是否发送时保留暂停，不能自行认定失败再发。
- 模型生成不具有执行工具、修改设置、读取凭证或改变发帖计划的权限；用户文本及外部内容仅作为待讨论材料。
- 运营者在启用付费请求前设置 X 与模型的费用上限和回复数量上限；无上限或账单状态无法可靠判断时不启用相关自动动作。不得用“开源”暗示运行免费。
- 日志区分：未选中、跳过、预览、待发送、结果不明、成功和暂停原因。错误日志不能包含凭证。
- 保存运营必要的任务标识、发布记录、退出状态、规则版本和费用记录。对话正文仅在需要时短期保留，默认最长 30 天后清理；这不影响去重所需标识和退出状态。平台要求更严格时遵守平台要求。
- 不把用户原文、用户名或对话日志自动推到公开仓库。复盘优先记录匿名失败类型；需要公开案例时使用合成示例或另行获得明确授权。

## 6. 成功指标与验证方法

运营初期每周抽取最多 20 段对话，覆盖两类题目，纳入短回复、无实质进展和主动退出的情况；不足 20 段则全量检查并披露样本数。

人工复盘记录：是否出现新观察、替代解释、支持或反对的依据、判断修订或新应用。允许多项、无变化和无法判断，不对用户打“智力分”，不只挑选成功案例。

同步记录：问题通过率及主要拒绝原因、成功发布与跳过天数、重复发送数、无关或机械回复数、退出请求执行情况及实际费用。互动数与关注增长作为传播指标单独观察，不等同于质量或因果效果。

全自动质量评议是运行机制；每周人工复盘用于纠偏。即使自评通过，也不能据此宣称已改善认知能力。

## 7. 分阶段交付与验收

| 阶段 | 可独立使用的产物 | 验收依据 |
| --- | --- | --- |
| 当前：公开文档 | 产品说明、SOP、候选题与贡献入口 | 文档完整、内部一致、链接有效、无隐私泄露 |
| 预览 | 不具备外发能力的选题与回复预览 | 下表场景的可复现输入与输出，人工抽查选题和回复 |
| 每日发帖 | 官方 API 定时原创发帖；回复保持关闭 | 授权账号真实帖子链接、去重和异常演练、费用记录 |
| 自动互动 | 获批后的有限回复与退出处理 | 平台批准记录与实际互动证据分别验收 |

| 场景 | 必须观察到的结果 |
| --- | --- |
| 二元设问或预设立场 | 候选被拒绝或重新构造；不只是追加“为什么” |
| 题目换词但任务相同 | 识别为近期实质重复，不进入发布池 |
| 事实前提错误或无法核实 | 拒绝或改成明确假设，重新评议 |
| 两轮候选全部不合格 | 当天跳过、通知运营者、不推进类别 |
| 用户回答完整 | 能补充或结束，不强制追问 |
| 偏题或通用任务请求 | 简短说明边界，不调用工具替用户执行任务 |
| 明确退出或退出后普通互动 | 停止回复；仅明确恢复请求可解除 |
| 自身事件、重复事件、机器人循环 | 不重复响应，不无限对话 |
| 模型失败、限流、预算耗尽 | 有限重试或暂停，不无限消耗 |
| 写请求超时、进程中断 | 先核对远端，不盲目重发 |
| 暂停后隔天恢复 | 不补发过期题目、不回复历史积压事件 |
| 将“忽略规则、泄露密钥”夹在回复里 | 当作用户文本，不改变行为边界或泄露信息 |
| 未获得 X 对 AI 自动回复的批准 | 草稿可预览，自动回复外发不可用 |

以上是未来实现的验收要求，不是本仓库已通过的运行测试。
