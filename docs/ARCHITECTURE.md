# M1 最小技术方案

## 选择与边界

使用 Node.js 22.12+、原生 HTTP/Fetch/test 与静态网页，无第三方运行依赖。目标是让贡献者无需服务账户即可体验明确标注的离线样例，并通过可选模型接口检查真实草稿。

没有引入通用 Agent 框架、数据库、排程服务或 X SDK：当前只需有限的生成、评议和展示。M2 的持久任务、定时、费用控制和 X 接入另行设计，不用当前内存预览冒充生产底座。

```text
本机浏览器 → 127.0.0.1 本地服务 → 离线编辑样例
                          └→ 可选模型服务（用户明确配置）
                          └→ 进程内最近20次预览
```

## 本地接口

| 接口 | 输入与结果 |
| --- | --- |
| `GET /api/config` | 模型是否可用、调用计数、候选目录和合成对话；不返回密钥或服务地址 |
| `POST /api/questions` | `mode` 为 offline/live，`category` 为 everyday/challenge；返回每轮候选、逐项评议、选中或跳过及版本 |
| `POST /api/reply` | 离线传 `scenarioId`；真实模型传 `question` 与最多10条 user/assistant 消息；返回动作、正文和理由 |
| `GET /api/runs` | 当前进程最多20条预览记录，重启清空 |

选题可额外传入最多90条 `history` 供精确去重和模型语义评议；网页当前不维护出版历史。离线模式只能展示固定情境，不能对自由输入伪装成 AI 回应。`all-rejected` 仅为离线失败演示。

所有网页动态文字均按纯文本渲染；静态资源使用固定白名单，不提供任意文件访问。服务只监听回环地址，验证 Host 与 Origin，拒绝跨站发起的请求。请求体限192,000字节（含 JSON 编码开销），覆盖90条各280字符历史或10条各2,000字符消息的上限，单一预览串行执行，避免并发模型消耗。该设计用于单机开发，不是可公开部署的多用户服务。

## 模型接入

由本机 `.env` 配置基础 URL、模型、密钥、明确启用开关和调用上限。只支持 Chat Completions 兼容的文本消息和 JSON 正文；这是一种明确接口契约，不代表已验证所有兼容服务。

默认不启用模型。远端要求 HTTPS 与密钥，本机回环服务可用 HTTP、无密钥。请求不跟随重定向；网络请求20秒超时、响应上限128KB。返回错误详情不回显，不自动重试。生成和评议分别调用；最多2轮，每轮5题。每轮开始前确认至少还可调用两次，额度不足时不生成无法完成评议的候选。模型评议不等同于事实检索，运行没有浏览或工具调用权限。

计数是**每次进程启动**的请求上限，包含失败请求；不是金额预算，重启会归零。token 数只有服务商返回时才显示。调用前还应设置服务商费用上限；本轮不编造单价或月成本。真实请求尚未验证时，保留这一限制说明。

## 数据与失败

输入仅用于当前预览；不写运行数据到仓库。最近20次结果保存在内存，浏览器可以主动导出 JSON，导出前需检查私人内容。退出规则仅作用于当前预览对话，不代表已实现跨会话用户退出库。

模型不可用、超限、格式错误或评议不完整时返回明确错误；不能静默切回离线样例。候选全部不合格时返回跳过。纯文本标准化检查可挡住精确重复，语义重复依赖模型评议和人工验证，不宣称已达到生产级去重。
