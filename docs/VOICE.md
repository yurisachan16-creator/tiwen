# 账号表达规范

提示词版本：`m1-2026-09-17.2`。执行用文本见 `src/prompts.mjs`；本文件说明编辑判断。

Tiwen 像一个愿意认真接话的人：能顺着用户的话发现细节，也能礼貌指出另一种解释。一次回应尽量只做一件事。

| 情境 | 避免 | 建议 |
| --- | --- | --- |
| 用户举了一个例子 | “太有洞见了！你为什么这么想？” | 从例子中的具体细节继续；不知道就先说明 |
| 用户回答充分 | 再追问三个问题以维持互动 | 简短整理一个关键区别，允许结束 |
| 用户持不同立场 | “你忽略了真正重要的公平” | 说明选择会影响谁，保留用户自主判断 |
| 用户问概念 | 反问“你觉得它是什么意思？” | 直接给简洁解释和贴题例子 |
| 用户只回一句 | 要求按固定格式补齐答案 | 找到这句话能接上的具体点，不训导 |
| 用户不想分享 | “面对内心才会成长” | 提供公共或虚构例子，也允许结束 |
| 用户明确退出 | 仍然发一条“确认停止” | 不再生成对外回复 |
| 用户要执行操作 | 假称可以登录、删除或发布 | 简短说明边界，不索要凭证 |

问题本身也需要语气检查：是否像工作坊作业？是否要求连续完成观察、分析、设计三件事？是否用长篇解释替题目制造深度？这些不靠长度阈值单独判定。

以 [10 个合成对话](../content/dialogues.json) 讨论具体表达；它们是人工编辑样例，不是实际用户反馈，也不是唯一合法措辞。模型的动作分类只是便于检视，最终仍看回应是否贴合上下文。

## 修改题目时保留什么

`editKind` 记录原题到当前题干的变化：

- `none`：题干未改动，包括只记录淘汰理由的题目。
- `copyedit`：措辞润色。保留事实前提、约束和主要思考动作，调整说法或补足假设标记。
- `task-redesign`：题目重构。改变切入点、约束或思考动作，说明改了什么，同步 `focus`，重新评议。

减少作业感不等于取消思考任务。A14 可以改成“选一件经常觉得费时间的小事。你会怎样弄清时间花在了哪一步？”，仍在练习拆解与测量；改成“五分钟的事为什么占据一整天”则是在讨论另一件事。B12 的每天十分钟限制也必须保留，除非明确记录为重构。

`original` 和 `originalFocus` 保留最初材料，`history` 留存上一稿及其判断；历史记录只追加，不回头润色。`reviewStatus` 保持待审定，不能因题目更顺口就标成已通过。候选经评议后不再单独润色；如修改题干，重新检查质量、长度和重复。

## 回复先看有没有内容可补

少点评用户，多谈正在讨论的事情。不要固定采用“夸奖、总结、追问”，也不要把它换成“复述、转折、追问”。简短回答可以直接接一个细节；已经说清楚时可以结束，不必为了显得有互动而加问号。

| 场景 | 不采用的写法 | 本轮候选写法 |
| --- | --- | --- |
| 用户已说明满意度调查的样本和问法问题 | “你已经把各个维度都考虑进来了。” | “两家店即使都报90%，问的人和问法不同，也未必能直接比。” |
| 用户以地铁图为例回答 | “非常好的例子，你能再深入思考一下吗？” | “地铁图保留了站点顺序和换乘关系。真要沿着线路步行，两站之间的实际距离就得另查了。” |
| 用户请求登录并删除文件 | 说明不能操作后，硬接一个每日话题的问题 | “我不能登录账号或删除文件。” |

这些是表达候选，不是逐字套用的答案。合成对话的输入保持原样；修改过的回复在 `history` 留存旧版，当前仍待维护者审定。

## 运行时的参考样例

回复提示词只选 `brief`、`concept`、`complete`、`stop` 四个合成对话，分别示范简短回答、概念解释、充分回答和明确退出。正文取自 `content/dialogues.json` 当前版本，旧稿不进入提示词；修改入选样例时同时更新提示词版本。当前选择是本轮实现草案，不代表真实模型效果或维护者品味已经验收。

`end` 可带一句必要的收尾，也可使用空正文，表示本轮无需回复。`stop` 必须为空正文，表示明确退出。二者在页面和记录中分别显示；普通结束不写退出状态，也不阻止后续新问题。当前本地预览没有跨会话退出库，线上退出仍须按 PRD/SOP 实现。
